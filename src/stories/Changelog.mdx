# Changelog

## 1.6.1

Added

- **`helpLink` takes its own icon and tooltip.** `helpLinkIcon` and
  `helpLinkTooltip` on `Labelled`, `Choice` and every control that wraps them,
  including per-choice on `ChoiceList` options. The icon was hard-coded to an
  information symbol and said nothing on hover, so a field advertising
  something specific — "this box takes markdown" — had to replace the entire
  label through the slot to change one glyph.

  ```html
  <TextField
    label="Notes"
    help-link="https://commonmark.org/help/"
    help-link-icon="mdi:language-markdown"
    help-link-tooltip="Supports markdown"
  />
  ```

Fixed

- **`TextField` no longer ships a debug outline.** The hidden mirror element a
  `multiline` field measures itself against carried `outline: 1px solid red`.
  It was invisible in practice — the element is `visibility: hidden` — but it
  had no business being in the stylesheet.

## 1.6.0

Added

- **Help text can be a slot.** `Labelled` and `Choice` take a `helpText` slot,
  and every control built on them forwards it — `TextField`, `Select`,
  `DatePicker`, `TimePicker`, `RangeSlider`, `ToggleSwitch`, `FileInput`,
  `ColorSelector`, `CalendarHeatmap`, `SegmentedControl`, `OtpInput`,
  `NavField`, `Rating`, `Checkbox` and `RadioButton`. Help text that needs a
  link, an inline value or a conditional warning no longer has to be built
  outside the field and positioned back under it.

  It WRAPS rather than replaces, so slot content still gets the help text
  styling — rich copy under a field still has to read as help text. The slot
  wins where both it and the `help-text` prop are given.

- **The `label` slot is forwarded too.** `Labelled` has always had it, and
  nothing that wrapped `Labelled` passed it through, so a field that wanted a
  control beside its label had to drop down to `<Labelled>` and rebuild the
  control inside it. The slot still hands out `className`, so the default label
  styling is one binding away.

- **`TextField` takes `maxHeight`.** A `multiline` field has always grown to
  fit what is typed into it; what it could not do was grow past `200px`, and
  that ceiling was out of reach — the rule lives at
  `.TextField__multiline .TextField_input`, which outranks anything a caller
  can put on the outside of the component.

  Any CSS length, or `"none"` for no ceiling at all. Reach for `"50vh"` more
  readily than `"none"`: a field that grows past the bottom of the screen takes
  the form's buttons with it. Also settable in CSS as
  `--octans-textfield-max-height`, for when the ceiling belongs to the layout
  rather than the call site.

- **`Popover` takes `surface`.** A popover hands your content through and
  paints nothing of its own, which is right for content that already dresses
  itself — an `ActionListMenu`, a date picker, a card — and wrong for a plain
  `<div>`, which floats transparent over the page. `surface` gives it the
  surface colour, border, radius and shadow, on the content's own root element.

  Off by default, because turning it on for everything would put a second
  border and a second shadow around every overlay that already has one. The
  styles are defined with `:where()`, so a rule of your own always wins.

- **`ScrollPane.scrollIntoView(target, options)`.** Scrolls the pane and
  nothing else. `Element.scrollIntoView` walks every scrollable ancestor, so
  calling it on an item inside a pane that lives in a dropdown or a sheet is as
  likely to scroll the page out from under the overlay as it is to move the
  list — which is why consumers kept hand-rolling this against the container
  they knew about. The pane knows which container it owns.

  Takes an element or a selector resolved inside the pane, and `block` /
  `inline` / `offset` / `behavior`. `block` defaults to `"nearest"`, which
  moves only when the target is off an edge and only as far as it takes —
  arrow-key navigation through a list wants a list that mostly does not move.
  Measured from bounding rects, so it stays correct where the target's offset
  parent is not the pane.

Fixed

- **`Popover` with `autoHide` no longer treats part of its own trigger as the
  page.** A click on the trigger is not an outside click, but reka reports it
  as one — its outside detection excludes the content layer and nothing else —
  so the popover has to recognise its own trigger or it would close and reopen
  on the same click. It did that by walking to its wrapper and taking
  `children[0]`, which is the trigger only when the trigger is a single
  element: a trigger with two roots had half of it counted as the page, and
  clicking that half closed the popover.

  It now asks whether the click landed anywhere in its own inline DOM, which is
  the trigger whatever shape the trigger is.

## 1.5.0

Added

- **`Sheet` has a `footer` slot.** A bar pinned below the scrolling content,
  for the save/cancel pair on a sheet long enough that the header actions have
  scrolled out of reach. It spans the sheet, and lines its contents up with the
  content above when `padded` is set; `footerClass` styles the inner wrapper.

  The footer lays its contents out as a row aligned to the end, and both halves
  of that are `--octans-sheet-footer-align` and `--octans-sheet-footer-gap`, so
  moving the actions to the other end is one declaration. Those defaults sit at
  zero specificity (`:where()`), so a class passed as `footerClass` wins
  outright instead of tying with them and being settled by stylesheet order.

- **`Sheet`'s size and animation speed come from the theme.**
  `--octans-sheet-size` (700px), `--octans-sheet-in-duration` and
  `--octans-sheet-out-duration` (700ms) are the defaults every sheet in an app
  now shares, instead of three literals repeated at every call site. The
  `size`, `animateInDuration` and `animateOutDuration` props still win per
  instance.

  `Sheet` slides by a `transform` it computes itself, so it reads these from
  the computed style rather than resolving them in CSS. They are re-read each
  time a sheet opens, so a theme applied mid-session takes effect on the next
  open.

- **`--octans-sheet-padding`** (30px) is the gutter `<Sheet padded>` puts
  around its content. It reaches the sheet as an inline style, so the
  declaration carries its own fallback — an undefined custom property with no
  fallback computes to no padding at all rather than to the old literal.
- **`--octans-icon-size`** sets the size of every `Icon` drawn without an
  explicit `size`. The default is `1em`, which is what Iconify already drew, so
  nothing moves; an app that wants roomier icons throughout sets it once
  (`1.25em` reads well against 14px text) instead of passing `size` at every
  call site.
- **`CardSection` takes `flush`**, which removes its padding entirely so a
  table, image or map runs to the edges of the card. `padded={false}` keeps its
  old meaning — horizontal padding off, vertical rhythm kept.
- **`--octans-table-header-border`** is the rule under a `DataTable` or
  `ResourceList` header.
- **`--octans-tint-{info,success,warning,error}`** — what a status Badge or
  Banner mixes its background FROM.

Changed

- **The `Sheet` and `Icon` dimensions are theme tokens.** They were declared in
  the global stylesheet with the page widths and the layout gutter, which meant
  the Theme Builder never listed them and a saved theme could not carry them.
  They now live in `tokens.scss` alongside the Tabs indicator, for the reason
  that section already gives: how wide a product's sheets are, and whether they
  glide or snap, is a decision worth carrying rather than a measurement.

  Nothing moves visually and no name changes — `--octans-sheet-size`,
  `-padding`, `-in-duration`, `-out-duration`, `-footer-align`, `-footer-gap`,
  `--octans-icon-size` and `--octans-icon-valign` keep their values. The two
  footer tokens had only ever been _referenced_ with fallbacks and are now
  declared, so they show up in the builder like the rest.

  `TokenKind` gains `'duration'` and `'keyword'`, since neither a `700ms` nor a
  `flex-end` is a length. The Theme Builder shows a colour picker for `color`
  and a text field for everything else, so both render correctly already.

- **`Sheet`'s `padded` is padding, and nothing else.** It also used to cap the
  content at a 900px measure and centre it. Content width is `size - 60px`, so
  that cap only engaged above `size: 960` — invisible at the 700px default, and
  then on a wide sheet the content silently stopped growing and drifted to the
  middle. A sheet is only as wide as its `size` says; content that wants a
  reading measure can set one itself.
- **Banner body copy is `--octans-text`.** The icon and the title still carry
  the status colour, which is what makes a banner readable at a glance; the
  sentence underneath was wearing it too, and paying for it — amber-brown on a
  pale amber wash measured 5.22:1 where body text measures about 11.
  `--octans-banner-ink` still overrides everything.
- **Warning banners and badges are amber rather than beige.** They were tinting
  from `--octans-warning`, which is deliberately the deep `warning-700` step so
  white label text clears 4.5:1 on it — and a 700 brown diluted into a surface
  is a muddy beige. The new `--octans-tint-warning` takes the hue's true mid
  step instead, the same way `--octans-rating` does. Every other role's tint is
  still its own fill, so re-seeding a role moves its banners as before.
- `--octans-banner-surface-strength` is 14% in light, up from 10%, and the
  banner's border went from a quarter-strength rule to 35%. At 10% a banner read
  as a slightly off-white panel rather than a coloured one.
- **The rule under a table header matches the rules between its rows.**
  `--octans-table-header-border` defaults to `--octans-border`;
  `--octans-border-strong` sits at 1.85:1 against a white surface where a row
  rule sits at 1.25, so the header was reading as a heavy bar. Set the token to
  `var(--octans-border-strong)` for the old weight. `border-strong` itself is
  unchanged, and still carries swatch outlines, the `Splitter` gutter and the
  heatmap's month separators.
- **`Page` keeps its primary action on the title row until 600px.** It used to
  go full width — and so, because the header wraps, onto a row of its own — at
  960px of page width, alongside the collapse of the secondary actions into a
  menu. A 900px-wide page has ample room for a title and a button on one line,
  so the header looked broken long before anything was cramped. The secondary
  actions still collapse at 960px.
- **A `DataTable` inside a `CardSection` respects the section's padding.** It
  used to cancel that padding with a negative margin so it met the card's
  edges — behaviour that was never designed, just what the stylesheet happened
  to do, and which made a table in a `padded={false}` section overhang the card
  by 16px on each side.

  For a table that runs to the card's edges, say so: `<CardSection flush>`. To
  cancel some other padding yourself, `CardSection` publishes what it is using
  as `--octans-card-section-padding-x` / `-y`, so you can negate the real
  number rather than restating `16px`.

- **`DataTable` no longer rounds its own bottom corners.** `.Table` and the
  last row's cells carried hardcoded `3px` bottom radii from before the radius
  tokens existed (`--octans-radius-box` is `8px`), and every cell in the last
  row got them rather than the outer two. They existed only to meet the card's
  corner once the table had reached it, which nothing does any more.

- **`Card` clips its content to its own corners** (`overflow: clip`). A card's
  corners are the card's business: `border-radius` rounds an element's own
  background and not its children's, so anything filling a card — a subdued
  section, a table, an image, a map — used to paint square corners over the
  rounded ones. Handling it per-child meant every such component had to know it
  might be inside a card, which is how `DataTable` came to carry corner radii
  in the first place.

  `clip` rather than `hidden`: `hidden` would make a card a scroll container
  and change what `position: sticky` inside it sticks to. `clip` does the same
  clipping without becoming one. It needs Safari 16, already the floor here for
  `color-mix()` and `@container`.

## 1.4.0

Added

- **Badge and Banner tint themselves from their own dials.**
  `--octans-badge-surface-strength` (18% light / 40% dark) and
  `--octans-banner-surface-strength` (10% / 18%) say how much of the role
  colour is mixed into the surface behind a status. One each rather than one
  shared, because a badge is a small object that has to hold its own against
  the card it sits on and a banner is a large panel where the same strength
  stops being a background and starts being a colour field.

  Each dial feeds four derived surfaces —
  `--octans-badge-{info,success,warning,error}-surface` and the banner set.
  Move the dial and all four follow; set one directly only when a single
  status should sit apart.

- `--octans-badge-ink` and `--octans-banner-ink` force one label colour on
  every status. Unset — the default — leaves each status wearing its own
  `--octans-text-<role>`.
- The Theme Builder filters by component. Pick `Badge` and the list drops from
  153 tokens to the 19 it actually reads. The map behind it is generated by
  `scripts/build-token-usage.mjs` from the component sources, so it cannot
  quietly describe a component that has moved on; `pnpm check:tokens` fails the
  build when it drifts, and runs as part of `pnpm verify`.

Changed

- Status badges are roughly twice as saturated. They were drawing the `-50`
  step of their role ramp, which works out at about 10% tint — pale enough
  that a badge read as a slightly tinted hole in the card rather than a chip
  sitting on it.
- Badge and Banner no longer read `--octans-<role>-surface`. That token is
  shared by seven components, so tuning a badge through it also moved Banner,
  Checkbox, FileInput, ProgressBar, RadioButton and Select. It still exists and
  those five still use it; only Badge and Banner have moved off.
- The contrast audit resolves a `var()` in a `color-mix()` percentage, which is
  what the derived surfaces need, and now covers all eight of them. It is what
  set the light default at 18%: at 20% the warning and error badges fall to
  4.47:1.

Upgrading

- **Badges will look different**, which is the point. If you had compensated
  for the old pale chip with your own CSS, drop it and turn
  `--octans-badge-surface-strength` instead.
- **The warning banner is very slightly cooler** — `254,244,230` becomes
  `244,237,231`. `--octans-warning` sits one ramp step deeper than the other
  roles (amber needs it to carry white text), so mixing from the role colour
  lands a touch greyer than the old `-50` step did. Set
  `--octans-banner-warning-surface` directly if you want the old cream back.
- **18% is the ceiling while labels stay role-coloured.** To go further, give
  the label a flat colour — `--octans-badge-ink: var(--octans-text)` — and the
  dial will carry 50% at better than 5.5:1.

## 1.3.1

Fixed

- The `.UIElement` text baseline is wrapped in `:where()`, so it no longer
  competes with the components standing on it. Every component root carries
  `.UIElement` _and_ its own CSS-module class, so a module setting `color` on
  its root tied with the baseline at (0,1,0) — and a tie falls to source order,
  which a component cannot rely on. Where the CSS is code-split, chunk
  stylesheets load _before_ the entry stylesheet holding the baseline, so it
  landed last and quietly outranked every one-class component rule.

  That is not hypothetical: it is what the built docs site was doing.
  `.UIElement` was sheet 48 of 50, so `<Button type="primary">` drew
  `--octans-text` on its dark fill at about 1.9:1 instead of the white
  `--_role-on-fill`. The buttons that still looked right were exactly the ones
  whose rule happened to carry two classes — `.hasColor.typeOutline` and
  friends — and so won the comparison outright rather than by luck.

  `:where()` contributes no specificity, so there is no tie left to lose:
  anything that matches beats the baseline, whenever it loads. It stays immune
  to a host page's `body { color }`, since an inherited value loses to any
  matched declaration.

Upgrading

- **Nothing changes for an app using the packaged CSS.** In `dist/style.css`
  the baseline already happened to come first, so component rules were already
  winning; this makes that guaranteed rather than a property of bundle order.
  The one thing that does change: a rule of your own that matches an Octans
  root element directly — `.my-card { color: … }` on a component — now beats
  the baseline where before it was a coin toss decided by load order.

## 1.3.0

Added

- `--octans-surface-neutral`, the background for a neutral chip sitting on a
  surface — `Badge` and `Tag` read it. Deliberately not `--octans-surface-sunken`:
  a well only has to read as _recessed_, whereas a chip has to read as an object
  of its own against the card it sits on, which at neutral-50 on white it did
  not. It is a registered token, so the Theme Builder offers it and a saved
  theme carries it.
- `Tabs` draws its selected mark from four theme tokens:
  `--octans-tabs-indicator-height`, `--octans-tabs-indicator-radius`,
  `--octans-tabs-indicator-offset` and `--octans-tabs-label-gap`. The app-wide
  choice of indicator belongs to the theme rather than to every call site; the
  `indicator` prop is a named shortcut that overrides them on one instance.
- `ActionList` items gained `content`, a render function that replaces the row's
  body for items that are more than text. `label` is still required — it stays
  the item's accessible, readable-back name.

Changed

- **`Tabs`' `theme` prop is gone, replaced by `indicator`.** `blue` and `purple`
  became `underline` and `bar`. Neither old value ever set a colour: both drew
  from the theme's own tokens, and the only difference between them was the
  shape of the mark, so the name described nothing it did. No alias is kept.
- The selected tab's mark is `--octans-primary`, not `--octans-focus-ring`. A
  selection is not a focus ring, and a theme that tuned its focus colour for
  visibility was moving tab selection with it.
- The mark is its own element rather than a `border-bottom` on the label, so it
  can be rounded and can sit off the label's box — which is what lets `bar` drop
  onto the container's divider. Default geometry is unchanged: same 52px tab,
  same 13px gap, same 3px rule.
- The `Select` caret is 20px, and rotates to point up while the menu is open. A
  rotation rather than a second icon: it costs nothing to fetch or bundle.

Fixed

- A tab that overflowed into the `…` menu lost its badge and its custom `tab`
  slot content — the menu row was the bare label. Both paths now render from the
  same function, so they cannot drift apart again. This is the moment a count
  usually matters most.
- `Select` ignored every fallthrough attribute. It set `inheritAttrs: false` and
  then never placed `$attrs`, so a `style`, `id`, `data-*` or native listener
  passed to a `Select` went nowhere at all. They now land on the field wrapper,
  so `style="flex: 1"` sizes the label and help text along with the control.
- Press-and-drag on a searchable `Select`: releasing the mouse over the search
  box closed the menu the drag had just opened. The release landed on neither
  the control nor an option, and the trailing click reached the document
  handler. It now keeps the menu open and hands the caret to the search, the way
  releasing over an option picks that option.

Upgrading

- **`<Tabs theme="…">` no longer does anything.** Replace `theme="purple"` with
  `indicator="bar"`; `theme="blue"` was the default underline, so it can simply
  be dropped. Better still, drop the prop entirely and set the
  `--octans-tabs-*` tokens in your theme, which is where an app-wide choice
  belongs.
- **Badge and Tag are a step darker.** If you were compensating for the old,
  too-light chip with your own CSS, remove it — or set
  `--octans-surface-neutral` to whatever you were compensating _to_, and nothing
  else moves.
- **A `style` you pass to `Select` now applies.** It was silently dropped
  before, so a stylesheet written around that will now be competing with it.

## 1.2.0

Added

- `@octans/ui/reset.css` — an opt-in page reset for apps where Octans owns the
  whole page. See the README.
- `ModalSection`, for dividing a modal's body into bands. `Modal` needed no new
  API: the body is a plain slot, so sections are just its children.
- `KeyboardKey`, a styled `<kbd>` for documenting shortcuts.
- `SkeletonPage`, the page-shaped placeholder for before a page's data
  arrives. It renders a real `Page`, so passing the same `size` means the
  content does not move sideways when it swaps in.
- `Page` is slotted throughout — `header`, `title`, `subtitle`, `help`,
  `breadcrumbs`, `secondaryActions`, `collapsedActions` and `loader`, each
  falling back to the markup it replaced. `title` and `subtitle` are scoped so
  a slot that only decorates the prop can still read it.
- `Page`'s measurements are tokens: `--octans-page-margin-top`,
  `-breadcrumb-gap`, `-title-gap`, `-content-gap`, `-title-size`,
  `-title-weight`, `-subtitle-size`, `-badge-gap`, `-action-gap` and
  `-loader-offset`.
- `Button` gained `loading` and `pressed`. `loading` keeps the button's width
  and its focus — it announces `aria-busy` rather than setting `disabled`.
  `ActionType` gained `loading` to match, so `PageActions`, `Modal`, `Sheet`,
  `Page` and `Card` actions all take it.
- `FileInput` gained `dropOnPage`, making the whole window a drop target.
- `Calendar` and `DatePicker` gained `minDate`, `maxDate`, `weekStartsOn`,
  `markers` and `timezone`.
- `setTimezone` sets a library-wide display time zone — the companion to
  `setLocale`. `Formatter` gained a `timezone` prop, and its date output
  follows the display zone rather than always the viewer's clock.
- `ToggleSwitch` gained `label`, `error`, `helpText`, `helpTextHtml`,
  `helpLink` and `required`, wrapping `Labelled` like every other control.
- `--octans-icon-valign` sets every icon's vertical alignment in one place.
  Defaults to `0`, which is what icons have always been drawn at.

Changed

- **`Popper` is now `Popover`.** It wraps reka-ui's Popover primitives and
  never had anything to do with popper.js. `Popper`, `PopperProps` and
  `PopperPlacementType` remain as deprecated aliases.
- The `.UIElement` baseline reads `--octans-font` rather than `--ui-font`, so
  the token the docs point at is the one that moves the font. `--octans-font`
  still resolves through `--ui-font`, so overriding either works.
- `--ui-sideNav-width`, `--ui-sideNav-maxWidth` and `--ui-globalNav-height` are
  now `--octans-sidenav-width`, `--octans-sidenav-max-width` and
  `--octans-globalnav-height`. The old names still work.
- `AppFrame` sets its own `height: 100dvh`. It had none, so the host page had
  to know to supply one — the stories all did, quietly.
- `Labelled`'s `required` draws an asterisk after the label instead of bolding
  the whole field, and is no longer deprecated. `TextField`, `Select`,
  `DatePicker`, `TimePicker`, `RangeSlider` and `FileInput` now forward it,
  along with `aria-required` on the control.
- `ToggleSwitch`'s root is now `Labelled`, so `class` and `style` land there.

Fixed

- `SkeletonCard` passed `{ props: { lines } }` to `SkeletonBodyText`, which is
  Vue 2 syntax — the prop never arrived (it only looked right because 3 is also
  the default) and the object came out as a DOM attribute.

Upgrading

Everything above is additive or aliased, with two exceptions that can move an
app that changed no code. Both are small, and both are worth a look before you
take the version:

- **`ToggleSwitch` renders a wrapper.** A `class` or `style` you pass now lands
  on the `Labelled` root rather than on the switch box, which is what makes it
  behave like every other form control. If you position a switch with your own
  class, check it — the class is one element further out than it was.
- **`AppFrame` sets `height: 100dvh`.** It declared no height before and took
  one from the host page. An AppFrame that is deliberately not full-page needs
  an inline `style` to override it; a class will not win the specificity tie.

## 1.0.0

First release.
